# Avatar Studio 0.5.0 · 外部素材工作流

目标：官方 DSH Desktop `0.2.2-rc.3` 和同机 DSH Web。安装 `dsh-charakuru-studio-0.5.0.tgz` 并启用后，在 DSH 左侧点 **Avatar Studio 工作台**。在「工程与关卡」先选已有工程，或填写角色设定并创建工程。使用每关旁的 **导入本步素材**，或在 **外部素材** 标签切换六关。

| 工序 | 允许登记 | 怎么继续 |
| --- | --- | --- |
| 01 原画与设定 | PNG 原画；PNG 设计参考/配色 | 原画点「采用」后才成为项目参考。替换已有原画会让相关视图重审。设计图可设为编辑器叠图，不替换项目原画。 |
| 02 拆件视图 | PNG，选择头部四视图、无头身体四视图或比例三视图之一 | 登记新版本后预览，点「采用」才替换选定槽。 |
| 03 头体候选 | 自包含 GLB，选头、体、配饰 | 预览后按部件采用。现有装配读已选头体；登记或采用不会调用 Tripo 或记为 Tripo 消耗。 |
| 04 装配与比例 | Blend 场景、自包含 GLB 追加部件、PNG 基色、PNG 比例叠图 | 点「带到 Blender 编辑器」再创建修订。GLB 追加到当前场景；贴图用于明确的网格和材质槽，要求已有 UV，保留其他通道。 |
| 05 权重与动作 | Blend 已绑场景、自包含 GLB 权重参考、VRMA 1.0 | 新修订保留原 rig；外部 GLB 仅追加为不导出的参考，不会自动转权。VRMA 可配 VRM 1.0 本机播放，不写入 Blend。 |
| 06 VRM 审阅 | Blend 待交付场景、VRM 1.0、VRMA 1.0 | 外部 VRM 配动作在本机预览，可暂停或重播；原样展示，不计作项目导出。需要新导出时，从可信 Blend 建独立修订再走原有导出与审阅。 |

**登记、采用、执行、通过关卡不同。** 登记把文件复制到工程 `materials/`，存储用 SHA-256 命名，按角色和槽位留记录。不会覆盖原文件、改选定输入或替用户通过关卡。采用使用已有原画、视图、候选校验。Blender 操作要求当前编辑基线和已登记的 `materialId`；成功时记录素材指纹与新修订，失败不替换基线。后期工序的实角视觉验收仍需人工。预览动作和基色处理不代表自动重拓扑、UV 展开、迁权、烘焙、许可核验或发布准备完成。

## 文件入口与边界

- **DSH 桌面**：项目目录由 DSH 官方目录选择器打开。使用原生文件选择或拖进素材区；能取得桌面桥提供的本机路径时，由同机 Host 读取副本。路径不可用时，直接把 File 的二进制传给同机 Host，不走 Base64。网页端也可用此方式。都可展开「从本机路径导入」；填 Host 所在机器上的绝对本机磁盘路径，不接受 URL、UNC 或设备路径。
- PNG 每件 20 MiB，VRMA 32 MiB，GLB/VRM/Blend 128 MiB；每工程最多 240 条登记、合计 2 GiB（按记录计算）。GLB/VRM/VRMA 使用 GLB 2、自包含缓冲区和贴图，不要求 Draco、Meshopt 或 KTX2 解码。扩展、容器与指纹检查并不保证材质、骨架或动作通用。
- Blend 支持未压缩与 gzip；Zstandard 压缩需要兼容的 Node（建议 24）。只检查解压头，不验证场景内容。建议先在 Blender 执行 `文件 → 外部数据 → 打包资源`，再另存。仅打开你信任且有使用权的场景。插件关闭源 Blend 自动脚本执行，但这不是第三方文件的安全隔离；不支持自动迁移外链库或缺失贴图。
- Agent：`charakuru_project` 的 `list_materials` 可按 `stageId` 查看当前工程登记（最新 40 条）。用 `charakuru_blender_avatar` 的 `editor_operation` 显式指定已选 `materialId` 及当前 `expectedRevisionId`。桌面的「创建修订」依赖本机 companion legacy 直接执行；如使用 3.1 Gateway，从 DSH Agent 接力，以真实 execution 上下文执行，不伪造授权。
- 所有新导入/预览只用本机。设定 `DSH_HOME` 的独立 Host 在自己的数据根保存最近工程与手工账本；不将用户全局 `.dsh` 当成独立 profile 的可写数据。包内有离线视口，不额外拉 CDN。安装/回退见 [Windows 指南](INSTALL-WINDOWS.md)。
