# Avatar Studio 0.6.1 · AI 优先与浏览器接力

安装 [`dsh-charakuru-studio-0.6.1.tgz`](INSTALL-WINDOWS.md) 时，核对工作台与 Host 同为 0.6.1。继续读写 `project.charastudio.json`；已有原画、候选、审批与 Blender 修订不被迁移成新工程。旧渲染记录仍可看。旧的 0.6.0 使用说明保留为历史，不是此版本按钮说明。

## 拉伸、塑形、对位和渲染

| 你要做什么 | 在哪里操作 | 接下来发生什么 |
| --- | --- | --- |
| 沿用现成骨架和网格，改比例或已有形态 | 素体改型 → 选体与头 → 打开采用的素体 → 拉伸和塑形 | 写例如「略高一点，收肩，不改头和脚底基准」。DSH 会话中的 Agent 读取当前对象、形态键、尺寸及骨架，决定参数并提交新修订。无需填 XYZ 或猜键名。 |
| 外部头模对版 | 登记并采用可信供体 Blend → 拉伸和塑形 → 外部头模接力 | Agent 先用只读 Blender 工序核对供体真实网格，不能用猜测名称提交。仍是有边界的刚性接入，不能自动焊颈、重绑眼口或迁控制器。 |
| 装配、权重、动作与 VRM | 原画路线后 3 关 / 素体路线「动作 / VRM」/ 三维编辑器 | 在相应工作区写目标。Agent 选择受限工序；核对源文件、已登记素材和活动修订。 |
| 改镜头、布光、构图 | 独立 AI 渲染台 → 写要求 → 登记并放入 DSH 会话 | Agent 选择镜头、取景、尺寸、颜色和光比，提交本机 Eevee PNG。酒红、冷室、中性示例只供学习，不默认套用，也没有本机一键套用方案。 |

**草稿不会发送。** 到 DSH 会话看过草稿再发送；没有当前会话时可在面板手工复制。旧 3.0.6 Companion 与 Gateway 3.1 均走原有协议适配；队列作业需在发起的 DSH 会话收集，不能伪造身份或换请求重发。回工作台刷新，在同一视口看修改前/后，再批准、或退回到原修订。渲染可以比较**同一模型修订**的两张 PNG，并单独批准或退回图像，不会批准模型。一次编辑执行有限工序，不做没有对应工具的自由网格雕塑。失败或缺少装备时不会用图生图冒充 Blender 渲染。

原画、拆件和比例图的「采用哪一张」可换选，也可选「不选图」/「取消采用」。候选和文件不删；清空槽以后即使再次扫描或生成也不自动填回。改原画须重审视图，改槽须重审该关与下游。按钮、标签和视角使用不透明高对比配色，不靠 DSH 壁纸衬底。

## Tripo Studio：开浏览器、交接、回收

Charakuru 使用用户登录的 Chromium 标签页，由有权限的 Agent 协助操作与下载；Tripo 不是内嵌页面。[Charakuru 教程](https://github.com/nanocle/Charakuru/blob/main/docs/tutorial.md) · [Tripo 官方 Studio](https://studio.tripo3d.ai/)。

1. **准备本机输入**。原画路线在头体候选关选择头或身体，每工单绑定相关的 4 张已审批 PNG（整体 11 槽须先审阅）。素体路线在「Tripo 衣 / 发 / 饰」登记并选择**独立部件参考 PNG**；不使用私有素体或头模 Blend。
2. **建工单，不上传**。填本次积分上限。这是本机的操作门，并不是供应商余额或报价。可打开官方 Studio、在原 DSH 会话准备草稿；没有连接浏览器工具也可手动照做。工作台不启动远程调试、不读取浏览器凭据、不代登录。
3. **确认上传、再确认报价**。先在工作台允许本工单的 PNG，才提供已校验的本机文件列表。用户或明确获准的浏览器工具只上传这组文件；拿到网页显示的真实报价后，登记并确认在上限内。**用户在网页手点一次 Generate**。不自动重试、不买积分、不转用 OpenAPI。看不清扣费状态先查官方历史。
4. **下载并比较**。每个结果导出自包含、未压缩 GLB。用桌面选文件、本地绝对路径，或放进工单回收目录（「核对工单与回收目录」查看）。DSH Agent 可用 `charakuru_tripo_quota(action="studio_collect", ticketId, fileName)` 登记该目录里明确的文件。头/体回候选视口；衣/发/饰回素体的部件预览与追加面板。回收不采用、不自动写积分账本，关闭工单不表示退款。已确认的旧工单即使输入变更仍可回收旧产物，不得重交。

每工程同一时刻只有一个打开的浏览器工单。工作台无法拦截用户在另一个标签页的手工消费，也无法证明远端价格或扣款。旧手工账本仍可登记核对后的实际消耗；与 API 余额分开。此版本未绑定任何 Tripo 帐号，也不承诺会话驱动、可用多图数量、实际价格、导出或免费重试权益。

## 文生图 / 图生图，以及每模型配置

- 在「模型与视图」明确选 **文生图** 或 **图生图**。文生图不读原画；图生图要先采用一张工程内 PNG，缺图或适配器不支持就停，绝不自动退回文生图。Qwen 的脚本导出是额外本机方案，不等于联机执行。
- 每模型都有 **Tip / 参数 / 提示词模板**。可执行适配器只显示已接线的选项。榜单模型只显示资料和提示词，不显示执行按钮或伪参数。
- 参数按工程、模型保存。**Anima** 可选分支、填本机 UNet/CLIP/VAE 权重文件名，改种子、步数、CFG、尺寸；无输入图。**Qwen ComfyUI Edit** 使用用户配置的参考编辑图，可覆盖种子、步数、CFG 和去噪。权重位置等宿主配置与工程参数分开。
- 模板按模型、槽位编辑。点「读取提示词模板」，改正向/负向后保存；可恢复内置版本。可用 `{character}`、`{reference}` 与 Anima 的 `{artist}`。参考图是否传输由模式与适配器决定，不靠一段文字。部分 HTTP 接口不单传负向提示词，负向仍保留在提示词清单。
- 在 DSH 宿主插件设置 `comfyuiUrl`（默认 `http://127.0.0.1:8188`；限本机回环地址）。Anima 使用自带图；Qwen 编辑另填 `comfyuiQwenWorkflowPath` 为可信 API 格式 JSON 文件的绝对路径。没有模板可先导出工作流，再按实际 ComfyUI 核心节点与本机权重配置。只接受预定的本机核心节点，必须把唯一参考图接到编码与采样链路；不安装节点、下载模型或启动服务。
- 预检只检查配置、参考图及模板，不报 GPU 已可用、不发云请求。再由用户执行；保存既有 ID 以免重复提交。换选图、槽位、模型或修改模板后应重新预检。生成失败先查本机队列或云账单。云接口默认关，仍需真实 API ID、专用凭据和单槽用户确认。

本版本的功能范围是**有审阅门的本机编辑与接力**，不是自动生产认证、Tripo API 客户端或通用 ComfyUI 图执行器。
