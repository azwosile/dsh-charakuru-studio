# Avatar Studio 0.6.0 · 双制作路线与本机渲染

适用：DSH `0.2.2-rc.3` 桌面主面板。工作台借鉴 Charakuru 的图库、候选对照和右侧检查器，不含原版程序、源码、样例或角色资产，也不运行 Codex。两种模式保存在同一个 `project.charastudio.json` 内。切换模式不重置审批、改换活动修订或消耗积分；制作两套不同角色时使用两个工程。

## 01｜原画重建

| 关卡 | 在工作台做什么 | 证据与决定 |
| --- | --- | --- |
| 原画 | 登记并采用 PNG，填写目标和手工预算 | 原画独立于 11 槽；可用真实角色设定作概念证据 |
| 拆件视图 | 左侧原画，正 / 左 / 右 / 背切到同朝向头＋发与无头 T-Pose 身体；导线只作屏幕对照 | 4＋4 张、比例 3 张。头部闭口、颈部无遮挡；水平 T-Pose，核对眼线、肩线、髋线和脚底。Qwen、Anima、NovelAI 与 AA 比较入口仍在 |
| 头体候选 | 单件候选编号与前、侧、背、顶、自由视角及线框；检查后分别采用 | 采用≠批准。Tripo 完整头体任务沿用原报价、人工提交、下载归档和证据门禁 |
| 装配比例 | 接入已核验的 Blender 检查点，或导入已准备好的 Blend；中央正交视口和右侧网格定位 | 原网格定位在新修订中完成。已有骨架不要直接缩放网格头部；用编辑器的明确头骨、颈枢轴操作，并检查颈缝 |
| 权重动作 | 保留有效骨架；在编辑器中指定权重来源、目标、最多转移距离和骨骼映射 | 动作探针只是有限值检查，VRMA 要配 VRM 1.0；外部文件不能代替项目导出 |
| VRM 复核 | 让编辑器从真实 Blend 修订导出，核对作者、表情、外部查看器，或开渲染台 | 后三关提供工序及修订视觉审阅；延续不可用实验回执自动通过正式交付门的边界 |

每关有「导入本步素材」。外部文件登记、采用、Blender 消费和人工审批是不同操作。控制台不依据文件名或候选预览自动填写证据。横线是屏幕辅助，不会自动拉伸图片或测量头身比。此版本不包含原版的智能重拓扑、全关自动修模或全部参考图生成服务。

## 02｜素体改型

**首选 YUMEKA v1.0.4 的 `Yumeka_Body` 和同场景 `Body` 面部；`RINNE_SotaiS` 作轻量素体备选，不把它当作完整头模。** 这是对本机候选的选型，不是内置资源。优先留同骨架的脸，随后做发型与衣饰；跨源接颈不应成为默认步骤。

| 候选 | Blender 5.3.0 实查 | 决定 |
| --- | --- | --- |
| YUMEKA 素体 | `Yumeka_Body` 13,197 顶点、14,138 面（12,230 四边面）、1 UV 层；单连通主网格，20 条单面共享边、未见 >2 面共边。已有权重和 53 个非 Basis 键，`Breasts_Big_1`、`Breasts_Width_1`、`Waist_corset` 有实际几何位移 | 首选成人曲线改型基底。测试用 `Breasts_Big_1=0.37` 及 Z ×1.05 建子修订；眼/口及 UV 不重造。先小量、逐键调整并复核衣服内侧 |
| YUMEKA 头 | 同 rig 的 `Body` 7,272 顶点、7,014 面（5,056 四边面）、1 UV 层；`Eye_L/R`、`Head`、舌部组及有效 `vrc.v_aa`、`vrc.blink (3.0)` 顶点位移；有多个独立网格岛、透明材质槽和 446 个非 Basis 键 | 首选同源面部。并非所有岛都应焊接；眼球、透明睫毛、牙舌与口腔独立检查。不能仅凭键名确认每个表情、眼睑贴合和颈圈无缝 |
| RINNE | `Sotai` 7,043 顶点、6,176 四边面、1 UV 层、53 骨、74 个含 Basis 的键；无完整脸，头/颈索引可查，原包另附贴图 | 轻量备选。打开前需在本机打包贴图、核对脖颈截面以及 donor 尺度；不要按 YUMEKA 眼/口结构假设自动匹配 |
| Felis | 体 10,313 顶点、10,216 四边面；脸 2,632 顶点、2,338 四边面，见双眼分组及发音键 | 更轻头拓扑对照；跨源移植、纹理与成人比例还需另验 |
| NATSUKO / RadDoll | NATSUKO 为混合头身对象，其 `Body` 检得 34 条 >2 面共边；RadDoll 头身可分，裸 FBX 审阅缺图 | 不作首发底模。仅供结构与表情参考；不跨工程自动替换 |

1. 在「选体与头」**登记**可信的、已在本地检查并 **Pack Resources** 的 rigged Blend，**采用**素体，点击「读取采用的素体，建 Blender 修订」。头模可选「保留随素体的同源面部」。安装包不会复制或自动导入本机私人参考库。
2. 「拉伸和塑形」选择已审计的网格、骨架、倍率 X/Y/Z（0.75–1.30）、已有形态键值（0–1）。绕脚底缩放 rig 与关联几何，保留顶点顺序、UV、形态键和权重；不重蒙皮。按名保留网格可将不想用的旧服饰或发型隐藏。对比中性与大幅扭转姿态，注意肩、肘、髋、胸腰、衣料穿模及另加零件是否随动。
3. 如必须用异源头，另登记头 Blend、选明确脸/眼/口网格、目标头骨以及尺度和位移；颈圈对齐后仅做刚性头骨跟随。它不会继承供体表情控制器、转移眼动骨骼或自动融合颈缝。沿鼻梁、眉眼、唇线、颧部、耳和下颌选成对 landmark，保留左右顺序，锁住颈圈以下，不用生成网格替代可编辑拓扑。用近距离正侧面与闭眼、张口动作检查。
4. 「Tripo 衣 / 发 / 饰」为每类生成**独立人工工单**，含用户输入的额度和实际合计报价对照；只用隔离的单件参考，不上传体、头、工程或其截图。由使用者在 Tripo 核对免费积分、可见性和可下载权限，再自行提交。返回的自包含 GLB 按服装、头发、配饰角色登记并追加到所选素体的修订。追加不等于对版、绑骨或审批；编辑器按部位移动、转移权重或用 Blender 手绑后复核。
5. 两条路线可以在 Blender 修订之后共用权重、VRM、VRMA 及渲染入口。部件测试夹具不能证明真实 Tripo 质量。正式导出仍要人工检查眼口、表情/眨眼、运动、碰撞及外部查看器。

## 独立 AI 渲染台

1. 左栏「独立渲染」；选择已经创建的**活动 Blender 修订**。确认 `revisionId` 和 Blend 指纹。写清风格、镜头、构图及最需要观察的部位。
2. 选择酒红舞台、冷调室内或中性检查，调主光/补光/轮廓光和曝光；支持四个方向、全身/头像、`640×800` / `960×1200` / `1280×720`。人物朝 Blender 的 `−Y` 为正面；非标准姿态模型先在视口确认。相机用保存的姿态帧，不计算新动作。
3. 「登记并放入 DSH 会话」只准备草稿，**按发送后**才交给会话中的 Agent。Agent 使用 `charakuru_render` 调受限配方、执行 Eevee 并报告真实静帧；3.1 队列须由提交的 DSH 会话/调用者收集，不能伪造身份。legacy 3.0 若连接可用，可对已登记请求手工试渲。状态不确定时先核对伴随回执，不自动重试。
4. `blender/renders/<请求ID>/` 保存 PNG 与回执。页面支持从同修订对照图片、下载、单独批准/退回。若活动修订已换，旧图只读；源 Blend、VRM、三维门及积分账本均不改变。

**审美取样**：MMD 实际文件是 1920×1080 / 约 30 fps；抽看约 6.96、15.18、23.41 秒。主要是酒红舞台、青蓝冷边光、浅色高光及清晰剪影。试玩分析中的下方补光、分层阴影和冷调为另一预设依据。优先保住脸、发和服装的明暗层次，避免复制游戏资产、素材或 Unity 数值。可选 Toon 是对兼容、不透明的 Principled 图做 Eevee 明暗阶，在渲染进程内改动，特殊透明材质或复杂着色器原样保留。未自动生成脸部 SDF、独立反壳描边、Bloom/LUT、动画或游戏管线复刻；渲染 PNG 不等于可交付模型。
