# 0.2.0：P0 / P1 实施与验收

日期：2026-11-18。目标：Windows 桌面 DeepSeek Harness **0.2.2-rc.3**。

## 已实现

- **桌面契约**：沿用桌面 Web renderer 的惰性模块工厂、`inject` 数组、侧栏入口和 main 整页工作台；仅 require 宿主 React，不依赖 CDN、iframe、Three.js 下载或外部字体。新增「图片与模型库」，共六个标签页。
- **运行诊断**：bootstrap 显示插件版本、Node、平台；伴随插件检查 `/health` 的实际结构、provenance、`/doctor`。支持显式 loopback 地址、旧 9877 与新 39877 探测；多个桥接同时命中时停止执行，要求指定正确地址。
- **Blender 3.0.6**：保留 `/headless` 与 `/act`，支持旧提升作业的收集。以本机已安装 runtime 源码核对协议。
- **Blender 3.1 Gateway**：依据上游源码实现身份 headers、`surface=queue` submit/collect；GUI 使用 `py=true`、明确 Blender sessionId 和 doctor 门禁。身份来自 DSH 工具执行上下文，不从页面伪造、不跨 Host 接管、不在拒绝后降级绕过授权。当前机器仍是 3.0.6，**3.1 只经过协议模拟测试**。
- **参考图预检**：执行前拒绝 Qwen 在线兼容接口、Anima 内置工作流、OpenAI 兼容接口对参考图的静默忽略；NovelAI Precise Reference 仅 V4.5；云端必须提供实际 API ID。Qwen 可导出参考编辑脚本再扫描导入。多个参考图也会拒绝静默取首张。
- **资产登记**：PNG 验证后复制为按 SHA-256 命名的不可覆盖版本；记录槽位、尺寸、来源名称、文件大小、时间。在线生成自动登记，离线生成可扫描标准 `views/<group>/<slot>.png`。支持文件选择上传 ≤20 MiB，路径导入 PNG ≤20 MiB / GLB ≤128 MiB。
- **GLB 候选**：归档不再自动选定。头/身/配饰候选独立登记，可显式采用。原创 Canvas 几何预览支持旋转、缩放、节点变换与基础色；**不支持纹理、蒙皮变形、动画、Draco/meshopt、稀疏 accessor**，最多 6 万三角形。较大或压缩模型请在 Blender 查看。任何 URI 外部资源都会拒绝，避免预览隐式联网或读取本机文件。
- **审批门禁**：原画字节与角色设定、11 个视图实际文件、已选择头/身 GLB 均绑定哈希证据。审批时重新读盘、核对 revision 和上游证据；缺图、篡改、未选择候选均不能通过。更换输入会使对应阶段及下游审批失效。Blender 执行前验证前三阶段；队列未收集时禁止重复提交。
- **工程列表**：最近 20 个工程记录在 `~/.dsh/charakuru-studio/recent-projects.json`。每个请求仍携带明确工程目录，不修改跨会话共享的“当前工程”。
- **HTTP 边界**：保持 loopback、Host / Origin / JSON 限制；新增每次启动的写入 session token，以及按资产 ID 提供内容、实时校验哈希、realpath 防越界。宿主提供 webServer origin 时使用精确 origin。**此 token 防跨站请求，不是人类身份认证；同机 Agent/进程仍可能访问本地 HTTP。**

## 尚未完成 / 不应误称完成

1. 没有安装或重启用户的 DSH，也没有升级伴随插件。仓库和打包产物不等于 desktop profile 已启用新版本。
2. 没有用真实 Blender 执行建模；没有调用任何收费生图、Tripo 或云端 API。
3. 图像字节有效 ≠ 多视图角色一致性通过；GLB 几何显示 ≠ 模型拓扑、纹理、骨骼、物理合格。
4. 0.2.0 **只开放前 3 阶段的证据审批**。后 3 阶段仍可生成/执行实验脚本，但工作台不再把草稿勾成可交付 VRM。P2+ 的比例、材质、权重、物理、表情与真实 VRM 查看器验收另做。
5. 新 Gateway 的 failed/canceled 作业需通过对应伴随插件工具处理并核对工程 pendingJob；不自动重试或消费额度。对无法确认终态的作业保留 ID，而不是假装未提交。
6. 未完成跨 OS 进程的工程写入锁、同机 Agent 与人工审批的强身份隔离。仅有进程内锁、revision 防覆盖及文件哈希门禁。

## 旧工程迁移

保留 `schemaVersion=1.0.0` 并兼容增加 `assets` 字段。0.1 工程没有证据绑定的已审批状态会在加载结果中重置到原画关卡，文件不会删除；下次写入才保存迁移结果。旧 `views` 文件通过“扫描生成的视图”重新登记；旧 GLB 通过路径重新导入并选择。

## 测试与边界

- Node 测试：44 项，覆盖旧功能、桌面模块契约、资产导入/选择/防篡改、旧工程迁移、Gateway 身份与队列、真实本地 HTTP。
- 静态检查：22 个 JavaScript 文件、7 个生成 Python 脚本 AST、包内资源路径。
- Chromium + React 18 + 模拟 DSH services：六标签页、真实 HTTP 缩略图、真实 GLB 三角形绘制、拖动改变画布、390px 无页面横向溢出、无 pageerror。
- **上述 UI 验证不是 Electron 桌面已安装验收**；需要安装后逐项核对。

## 桌面验收步骤

1. 保留当前 0.1.0 包和 profile 备份，确认退出桌面后，按 `INSTALL-WINDOWS.md` 安装 0.2.0 tgz。
2. 启动桌面，确认侧栏入口、六标签页、bootstrap 版本 0.2.0；若端口冲突，在插件配置与工作台连接地址同时修改。
3. 新建测试工程。导入一张 PNG，检查缩略图；扫描已有 11 张视图。缺图时提交审批应被拒绝。
4. 导入自包含未压缩 GLB，查看几何、选择头/身；确认仅归档不会自动改变选定模型。
5. 通过前三阶段后更换一个视图，确认视图关卡与后续审批失效；不要用生产工程做破坏性篡改试验。
6. Probe 3.0.6：核对 provenance 与 doctor。只有 GUI ready 才可选择 GUI 执行；先生成脚本，不自动运行真实生产模型。
7. 未来升级 3.1 时，在同一 DSH Host 会话使用 `blender_session` 建立授权后，再验证 submit / collect 与 GUI py 路径；不凭本轮模拟测试宣称兼容性认证。

## 复现

```bash
npm run build:client
npm test
npm run check
npm pack
```

`lib/client-preview.js` 是原创几何预览源；`build:client` 仅把它嵌入 `lib/client.js` 标记区，不需第三方打包器。构建后的 client.js 已随包提供。
